Run the **H1 handoff — Requirement → Design (Product → Developer)** for issue $1.

Read `.github/mainline.json` and `.github/project-fields.json` for the project parameters and the
field/option IDs. If either is missing, stop and say which.

## 1. Run the checks

The checklist is **`/mainline-requirement-workflow` step 4**. Read it there and verify each line against the
issue and the repo — do not work from memory, and do not accept a check you cannot evidence.

What each line means in practice:

- The `.feature` file exists in the repo, and every scenario is Given/When/Then and testable.
- Every scenario traces to an observation or a stated rule. A scenario citing neither is a guess —
  fail the check and name the scenario.
- Terms match the glossary or the existing Tonto model under `domain/`. A new synonym for an
  existing concept fails.
- **Non-functional requirements stated or explicitly N/A** — auth and SSO, tenancy, performance,
  compliance, retention. An unanswered line is a failure; "N/A" is a pass.
- Out of scope stated explicitly.
- Prototype or screenshots attached wherever there is UI.

## 2. Block on failure

If any check fails: report which one, quote what is missing, and **stop**. Do not move `Phase`, do
not assign, do not notify. Say what would satisfy the check.

## 3. Move, assign, notify, record

Only when every check passed:

- Set `Phase` to **Design**.
- Assign `$2`, or `assignees.design` from the config. If neither resolves, stop — do not move an
  unassigned card.
- Notify via the config's `notify` command, attaching the `.feature` file, the prototype or
  screenshots, the NFR answers and the scope boundary. The developer should be able to start without
  asking Product anything.
- Comment on the issue recording the result: the handoff, who signed, who it went to, and the time.

Report what moved and what was attached.
